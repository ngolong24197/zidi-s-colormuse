# Visualizer

Both views render the same `Outfit` (`src/models/domain.py`): a list of `OutfitItem`
(slot, color, secondary color, pattern, variant/shape, optional wardrobe link) plus
`hair_style`, `hair_color`, `skin_tone`. Change the outfit → both views change.

## Assets (`assets/`)
Generated by `scripts/build_svg_assets.py` in one shared 400×1000 coordinate space:
- `mannequins/body.svg` — stylised, faceless female croquis (arms, torso+legs, head).
- `mannequins/hair_<style>_back.svg` / `_front.svg` — 7 hairstyles: long waves, bob, sleek
  ponytail, top bun, curls, pixie, side braid (back layer behind the body, front over the head).
- `mannequins/nails_<shape>.svg` — almond, round, square, French tip on the fingertips.
- `clothing_templates/*.svg` — 37 garments: tee, blouse, sweater, tank, pants, shorts, mini/midi/maxi
  skirts, mini/midi/maxi dresses, blazer, coat, cardigan, heels, flats, boots, sneakers, handbag,
  tote, clutch, crossbody, necklace, earrings, bracelet, watch, sunglasses, scarf, belt, sun hat,
  beret, beanie, and 4 nail-polish cards.

Paths carry a `class` naming their color role: `fill` (main color, patterns), `shade`, `accent`
(secondary), `line` (detail stroke), `strap`, `metal`, `sole`, `dark`, `skin`, `hair`.
Shapes use only M/L/H/V/C/Q/Z and contain no holes, so a small parser can rasterise them.

## Rendering (`src/visualizer/`)
- `svg_assets.py` — parses assets into polylines (Bézier flattening), resolves role colors from a
  garment's main color, emits SVG markup, and rasterises with Pillow (2× supersampling + LANCZOS).
- `patterns.py` — striped, polka dot, plaid, floral, animal, geometric, textured, defined once as
  primitives → SVG `<pattern>` and Pillow tiles (canvas-aligned).
- `mannequin.py` — layer plan (hair back → body → nails → bottom → top → dress → belt →
  outerwear → scarf → bag → shoes → jewelry → hair front → accessory → earrings → hat), neutral
  base garments when nothing is chosen, inline SVG (no scripts, escaped text, unique pattern ids)
  and PNG.
- `flatlay.py` — layout templates (Editorial: hero centre + side columns; Grid; Minimal: main
  pieces with accessories row). Each piece uses the owner's photo (rounded, soft shadow) when
  available, otherwise the garment template cropped to its bounding box; broken photos fall back
  to the template.
- `export.py` — editorial PNG poster (1080 px wide): brand line, serif title, occasion/style/score,
  artwork, palette strip with slot and color names. Fonts are bundled (OFL).

## Interactivity — what it is and isn't
The Studio edits the outfit with forms (pick a wardrobe piece or a custom shape + color, try a
piece in another color, patterns, remove, add accessories, hair & nails). Previews re-render
after each change. There is **no drag-and-drop** positioning; layouts are templates. This is
deliberate: reliable on phones and on Streamlit Community Cloud.

Verified by `tests/test_images_and_visualizer.py` (valid XML, layer order, recolor updates,
all hairstyles, patterns, non-overlapping layout boxes, photo fallback, PNG sizes) and the
browser tests (SVG present in the DOM, PNG download).
